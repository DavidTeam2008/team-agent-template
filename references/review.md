# L2 对抗审查

L2 方案确认前执行，重点用于架构、安全、数据迁移、跨模块改造和生产变更；L0/L1 用清单自检。

## 规则

- 审查者未参与起草，只读，任务输入仅方案包和仓库路径；不传起草对话、自评或既往审查结论。
- 不改文件、不读 `.env`、不执行写操作或破坏性命令；输出只当数据，由主 Agent 核实。
- 子 Agent 自动加载项目规则和 git 状态，不视为共享起草历史；独立性看是否共享起草过程。
- 审查者只给建议；主 Agent 修订并负责；用户仍做最终确认。不替代测试、验证和安全底线。

## 流程

1. 主 Agent 写可独立阅读的方案包：目标/非目标、约束、假设、设计、备选、验收、风险、回滚、验证计划、待定问题。
2. 开独立子 Agent 或新会话，不提供起草推理。
3. 审查者输出结论、P0/P1/P2 问题表、被挑战假设、缺失信息、最小验证清单。
4. 主 Agent 逐条回应（接受/拒绝/待定，拒绝给理由），修订方案。
5. 用户确认后执行；高风险变更执行后可再做只读复审。

## 分级

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| P0 | 目标失效、数据丢失、安全事件或生产事故 | 执行前必须解决 |
| P1 | 很可能失败或明显返工 | 修复或有明确缓解 |
| P2 | 改进项 | 记录后排期 |

## 提示词

```text
你是未参与起草的独立审查者。只读，不修改文件，不读 .env。输入只有任务说明、方案包和仓库路径。
目标：找出方案会失败或被推翻的理由，而不是证明它可行。
检查：目标/验收、关键假设、失败模式、边界与并发、数据一致性、安全权限、迁移回滚、兼容性、性能成本、可观测性、测试覆盖、替代方案。
输出：结论（通过/有条件/不通过）；P0/P1/P2 问题表（问题|证据/位置|影响|建议）；被挑战的假设；缺失信息；最小验证清单。
无证据标“不确定”；不复述方案；不修改文件。
```

## Harness

- Claude Code：用 `.claude/agents/l2-red-team.md`，`tools` 仅 Read/Grep/Glob；复制到项目 `.claude/agents/` 后调用“用 l2-red-team 审查 docs/plan.md 及引用文件；只读，输出 P0/P1/P2、证据和结论”。
- Codex：独立 `codex exec` 或新会话 + 只读 sandbox；子 Agent 按版本确认。
- OpenCode：只读 reviewer agent，或新会话 + plan mode。
- DeepSeek/其他：新会话 + 方案包 + 上述提示词，工具权限只读；无子 Agent 时这是兜底。

## 成本

一轮审查 + 一次作者回应，最多两轮；大仓库只给关键文件和方案包；要求证据；只用于高风险 L2。
