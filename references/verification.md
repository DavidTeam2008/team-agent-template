# 验证细则

## 最低验证

| 变更类型 | 最低验证 |
| --- | --- |
| 文档/配置 | 链接、渲染、字段和事实核对；必要时运行校验脚本 |
| 代码 | 项目已有 lint、类型检查、测试和构建 |
| UI/交互 | 本地启动并实际操作主路径和关键边界；必要时真机/多浏览器 |
| 数据/迁移 | 隔离环境验证迁移、回滚和数据一致性 |
| 依赖升级 | 锁文件一致性、构建、相关测试、关键路径冒烟 |

无法运行写“未运行”及原因；UI 不能操作写“未验证”+手动步骤，不声称已验证。

## 长任务记录

- 计划文件：L1/L2 长任务至少维护一个持久文件（如 `MEMORY/todos.md` 或 `docs/plan.md`），会话内任务列表只作视图。
- 计划内容：目标、非目标、验收标准、检查点、风险。
- 检查点：可恢复快照（commit/stash/patch/备份）+ 已验证状态；回滚前先保存未提交改动。
- 验证记录：命令、结果、失败原因、下一步；环境/网络/已知 flaky 单独标注，不计入修复次数。

## 失败处理

- 先定位原因再修改；同一失败检查修复 2 次仍失败，或同一子任务 3 轮修复-验证仍无进展时停止。
- 环境/网络/已知 flaky 不计入修复次数，记录后换验证方式。
- 达到约定时间、token 或轮次预算时停止并汇报。
